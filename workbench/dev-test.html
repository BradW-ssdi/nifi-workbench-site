Not in scope

  • Real data, routes, and permissions. Links that go nowhere use #. Data is static.
  • Components that have no screen yet (see the Components page for what exists).
  • Dark theme.
  • Figma prototype fidelity beyond the frame: the Figma screens are reference images with a working rail, header, and footer.

How to test each screen

  1. Frame. Run the checklist on screens/frame.html once, then spot check it on every other screen: the current rail item is correct, the logo returns Home, the rail state carries between screens.
  2. Keyboard only. Tab through the whole page. Focus is always visible, the order makes sense, every control works with Enter or Space, Escape closes menus and dialogs, and focus returns where it came from.
  3. Zoom. At 200% and 400% (or a 640px and 320px wide window): one column, no sideways scrolling of the page, every control reachable. Only data tables may scroll sideways, inside their own box.
  4. Screen reader. NVDA with Chrome or JAWS with Chrome: the page title, one h1, landmarks (Main navigation, Breadcrumb, Footer), and every announcement in the screen's contract (sort, filter counts, errors, confirmations).
  5. Automated. axe DevTools, or the vendored axe from the console (see docs/accessibility.md). We see zero violations on every screen in scope. Two known "needs review" items: the Add Algorithm comments field while the sticky header overlaps it, and color contrast on the Components page, where specimens sit on gradients and overlays. Check those by eye.
  6. Build it. Pick one screen and build it in the app from its template and the contract in docs/dev-handoff.md. Note anything in the template or contract that was unclear, missing, or hard to do in Thymeleaf and HTMX.

Reporting

For each finding: the screen, the steps, what you expected, what happened, browser and zoom level, and a screenshot. Say whether it is a bug in the template, a gap in the contract, or a question about the design.
