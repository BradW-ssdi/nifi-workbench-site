Button with icon

Accessibility — 508 / WCAG AA
  • Use a real <button> — never a styled <a> or <div> with a click handler.
  • Icons inside labeled buttons carry aria-hidden="true"; the visible text is the accessible name.
  • Disable with the disabled attribute, not a class — it removes the control from the tab order correctly.
  • Focus is a 3px ring with a white gap (never removed); contrast: white on #2C6777 = 7.0:1, on #D40032 = 6.3:1 — both pass AA and the primary passes AAA.
  • Min target 40px tall (2.5.8 AA is 24px — met with margin). Reflows without clipping at 320px width (400% zoom).

Accessibility — 508 / WCAG AA
  • Every control has a programmatic label: a <label for>, or aria-label when no visible label exists. Placeholder text is never the label.
  • Required fields carry the required attribute; the red asterisk is presentation only.
  • Errors set aria-invalid="true" and tie the message with aria-describedby; the message names the field and the fix (3.3.1, 3.3.3). Help text is tied the same way.

Accessibility — 508 / WCAG AA
  • Badges convey status with text, never color alone; all five pass 4.5:1 (Open 4.7, Closed 5.3, Pending 8.0, Active 4.7, Danger 6.3).
  • An alert injected after load gets role="alert" (danger/blocking) or role="status" (confirmation) so screen readers announce it. Alerts present at page load need no live role.

Accessibility — 508 / WCAG AA
  • Real <table> semantics: <th scope="col"> on every header and a <caption> (visually hidden is fine) naming the table.
  • Sorting is an action — the header control is a <button class="ds-sort-btn">, never a link. The sorted column (and only it) carries aria-sort="ascending|descending", and each re-sort is announced through the page's live region.
  • Icon-only row actions each carry an aria-label that names the row ("Edit 000_A_HepB_CI"), not just "Edit".
  • Row hover highlight is enhancement only — no information lives in hover.
  • A flagged row (tr.is-flagged, warning tint + inset bar) always pairs with a visible ds-badge-warning in a cell — the tint alone is never the message (1.4.1). See the Manage Conditions view.
  • Wide tables scroll inside .ds-table-scroll so the page itself never scrolls two ways at 400% zoom (1.4.10); the wrapper is keyboard-scrollable when it clips.
  • Pagination is a <nav aria-label="Pagination">; the current page carries aria-current="page"; prev/next are labeled buttons.

Tab bar

Basic criteria fields render here.
Accessibility — 508 / WCAG AA
  • The bar is role="tablist" with an aria-label; each tab is a <button role="tab"> with aria-selected and aria-controls pointing at its role="tabpanel".
  • Roving tabindex: only the selected tab is in the Tab order (tabindex="-1" on the rest); Left/Right arrows move between tabs.
  • Selection is shown by the 3px underline plus weight change — not color alone. aria-selected="true" drives the same visual via CSS.
  • Tabs wrap to a second row at narrow widths instead of clipping (1.4.10).
